# Security policy

## Reporting a vulnerability

Please **do not** open a public issue for security problems. Report them privately through GitHub's private
vulnerability reporting: on this repository, go to **Security → Report a vulnerability** (this opens a draft
Security Advisory visible only to the maintainers).

Include what you found, how to reproduce it, and the impact you expect. We aim to acknowledge reports within a few
days, and we will keep you updated until a fix is released. We are happy to credit you in the advisory.

## Supported versions

findaro is pre-1.0. Security fixes go into the `main` branch and the latest release.

## Security model (what to expect)

- **Two keys per project.** Creating a project returns an `admin_key` and a `search_key`. Keys are stored hashed.
  - The **admin key** manages the project (documents, imports, schema, settings, deletion). Keep it server-side.
    The API refuses admin keys on requests that carry a browser `Origin` header.
  - The **search key** is browser-safe: read-only, limited to `/v1/search` and `/v1/chat` for its own project.
- **Allowed origins.** Browser requests with a search key are accepted only from the project's `allowed_origins`
  (`PUT /v1/projects/{id}/settings`). localhost is allowed by default for development; set
  `FINDARO_ALLOW_LOCALHOST_ORIGINS=false` in production. Server-to-server calls (no `Origin`) are not affected.
- **Bootstrap token.** If `FINDARO_BOOTSTRAP_TOKEN` is unset, anyone who can reach the API can create projects (the
  API logs a warning). Always set it on any deployment others can reach; `POST /v1/projects` then requires
  `Authorization: Bearer <token>`.
- **Rate limiting.** Per-key, in Redis (`FINDARO_RATE_LIMIT_PER_SECOND`, default 50).
- **LLM output.** Chat answers are generated by a model from catalog data, then checked sentence by sentence in
  code. Catalog fields are untrusted input: the widget only follows `http(s)` product links and renders catalog
  text as text. If you supply a custom `renderProduct` that returns HTML, escape document fields yourself.
- **Query log.** `FINDARO_QUERY_LOG` writes end-user queries to disk. It is off by default outside docker compose;
  decide on retention before enabling it in production.
- **docker-compose.yml is for development.** It uses fixed Postgres credentials, disables the OpenSearch security
  plugin and publishes service ports on the host. Don't expose it to the internet as-is.

Issues in these areas (for example, a way to use a search key to modify data, bypass `allowed_origins`, read
another project's documents, or make a chat answer state an unchecked number) are in scope.
