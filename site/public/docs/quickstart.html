Quickstart

From keys to working search in about five minutes. You need curl and, for the nicer output, jq.

1. Get a project and keys

Hosted beta

We send you a project id and two keys when we set up your account. Put them in your shell:

export API=__API_URL__
export PID=prj_…            # project id
export ADMIN=fdr_admin_…     # server-side only
export SEARCH=fdr_search_…   # browser-safe

Self-hosted

Create the project yourself. If the API was started with FINDARO_BOOTSTRAP_TOKEN (it should be, anywhere others can reach it), send that token:

export API=http://localhost:8000
curl -s -X POST $API/v1/projects -H "authorization: Bearer $FINDARO_BOOTSTRAP_TOKEN" \
  -H 'content-type: application/json' -d '{"name": "my-store"}' | tee project.json
PID=$(jq -r .project_id project.json); ADMIN=$(jq -r .admin_key project.json); SEARCH=$(jq -r .search_key project.json)

2. Import your catalog

Upload a .jsonl, .json or .csv file (up to 50 MB). Each document needs a unique id field (any name, present in every document); everything else is up to you. The import runs as a job:

curl -s -X POST $API/v1/projects/$PID/import -H "authorization: Bearer $ADMIN" \
  -F file=@catalog.jsonl | tee job.json

curl -s $API$(jq -r .status_url job.json) -H "authorization: Bearer $ADMIN" | jq '{status, succeeded, failed}'

Repeat the status call until status is succeeded (or completed_with_errors, with the failing rows listed). Most of the time goes into computing embeddings.

Prefer pushing JSON? Send up to 10,000 documents per request. Documents are upserted by id:

curl -s -X POST $API/v1/projects/$PID/documents -H "authorization: Bearer $ADMIN" \
  -H 'content-type: application/json' \
  -d '[{"id": "SKU-1", "title": "Cotton kurta", "price": 799, "color": "White", "category": "Apparel > Men"}]'

3. Check the inferred schema

curl -s $API/v1/projects/$PID/schema -H "authorization: Bearer $ADMIN" | jq -c '.schema.fields[] | {name, role}'

If a role is wrong (say a numeric field that isn't a price), send the same fields list back with PUT /v1/projects/{id}/schema. See the API reference.

4. Search

curl -s -X POST $API/v1/search -H "authorization: Bearer $SEARCH" -H 'content-type: application/json' \
  -d '{"query": "kaale joote 1000 ke andar", "size": 5}' \
  | jq '{total, chips: [.understood.chips[].label], hits: [.hits[] | {id, title: .document.title}]}'

Explicit filters and sorting work alongside (or instead of) natural language:

{
  "query": "cotton kurta",
  "filters": { "color": ["White", "Cream"], "price": { "gte": 300, "lte": 1500 }, "category": "Apparel > Men" },
  "sort": "price:asc",
  "facets": ["color", "brand", "price"]
}

5. Allow your website's origin

Browsers may only use the search key from origins you allow (wildcard subdomains are fine):

curl -X PUT $API/v1/projects/$PID/settings -H "authorization: Bearer $ADMIN" \
  -H 'content-type: application/json' \
  -d '{"allowed_origins": ["https://shop.example.com", "https://*.example.com"]}'

6. Add the widget

One script tag and one element, anywhere on the page:

<script src="__SITE_URL__/findaro-widget.js" data-project="prj_…" data-key="fdr_search_…"
        data-base-url="__API_URL__" defer></script>

<findaro-search></findaro-search>

That's it: a search box with a Search / Ask AI toggle, removable chips, filter pills, a product grid and a product drawer. Customise it in the widget guide, or build your own UI with the SDK.

Never put the admin key in a web page. It's refused from browsers anyway, but treat it like a password.
