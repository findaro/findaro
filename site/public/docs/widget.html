Integrate

Widget

<findaro-search> is a Web Component (Shadow DOM, no framework, no dependencies, about 20 KB gzipped with the SDK included). It works in any page: plain HTML, React, Vue, a CMS template.

Install

<script src="__SITE_URL__/findaro-widget.js" data-project="prj_…" data-key="fdr_search_…"
        data-base-url="__API_URL__" defer></script>
<findaro-search></findaro-search>

Settings on the script tag (data-project, data-key, data-base-url, data-locale, data-mode, data-layout, data-starters, data-badges, data-card-actions) apply to every <findaro-search> on the page. Attributes on an element override them. Self-hosting? Build the file with npm install && npm run build; it's at packages/widget/dist/findaro-widget.js. Serve it from your own domain.

What it renders

  • One search box with a Search / Ask AI toggle. Search runs as you type; Enter searches, Escape clears.
  • Understood chips (“Under ₹1,000”, “Black”) that the shopper can remove.
  • Filter pills for the attributes that split the current results, behind a “Filters” button.
  • A product grid (image, title, price, rating), with exact matches first and close matches marked.
  • An AI panel: streamed answers, cards for the products it cites, clarifier chips (“Show slightly over budget”) and a clear no-match state.
  • An Ask button on every card that opens a product drawer: details, suggested questions and a chat about that one product.

AI Mode

In AI mode the widget is a conversational shopping assistant. Products appear inline in the conversation instead of a separate grid. Add layout="page" for a full-page version with a chat history sidebar (a drawer on phones) and a composer fixed at the bottom. Give the element a height; it fills it.

<style> findaro-search { height: 100dvh; } </style>
<findaro-search mode="ai" layout="page" badges="material,tags"
                starters="black shoes under 1000|kurta for a wedding|steel water bottle"></findaro-search>
  • Each answer shows How I searched: what the query was understood as, any filter that was loosened to find results, the result count and the time taken.
  • Cards show how well each product matches the request (“Matches 2/2”, “Matches 1/2 · not Leather”, “Leather not listed”). The API works this out from each listing.
  • Up to three one-click next steps (“Only Copper”, “Under ₹700”) follow each set of results.
  • Shoppers can select 2 or 3 products and choose Compare, which shows a side-by-side table built from the listings, or Ask about these, which sends their next question about those products only.
  • Conversations are saved in the shopper's browser (localStorage, per project, up to 30). The search key is never stored. A conversation reopened after 30 minutes starts a new server session, and the widget re-asks the last question when it needs to.

Without layout="page", mode="ai" shows the same conversation inside the widget box, under the Search / Ask AI toggle.

Properties and methods

NameWhat it does
el.search(query)Run a search programmatically (or ask, in AI mode).
el.onProductClick = (hit, event) => …Called when a product is clicked. When set, the widget doesn't follow the product URL.
el.renderProduct = (hit, { display, formatPrice }) => …Your own product card. Return an element, or an HTML string (escape document fields yourself).
el.cardActions = [{ label, onClick(hit) }]Extra buttons on AI Mode cards, after the ones from card-actions. onClick runs unless a findaro:action listener cancels the event.
el.strings = { … }Override any UI text, merged over the locale's defaults.
el.clientInject a preconfigured SDK client (for example with a custom fetch).
 
<script>
  const el = document.querySelector("findaro-search");
  el.onProductClick = (hit) => location.assign(`/p/${hit.id}`);
  el.renderProduct = (hit, { display, formatPrice }) => {
    const card = document.createElement("div");
    card.className = "my-card";
    // textContent keeps catalog data safe
    card.textContent = `${hit.document[display.title]} · ${formatPrice(hit.document[display.price])}`;
    return card;
  };
  el.strings = { placeholder: "Search 10,000 products…" };
</script>

Events

All events bubble and cross the shadow boundary (composed).

EventdetailWhen
findaro:resultsthe search response (total, hits, understood, …)After each search returns.
findaro:product-click{ hit }A product was clicked. Cancelable: preventDefault() stops navigation to the product URL.
findaro:action{ action, hit }A custom card button was clicked (action is its label). Cancelable.
findaro:errorthe errorA request failed.
 
el.addEventListener("findaro:results", (e) => console.log(e.detail.total));
el.addEventListener("findaro:product-click", (e) => {
  e.preventDefault();
  openQuickView(e.detail.hit);
});
el.addEventListener("findaro:action", (e) => {
  if (e.detail.action === "Add to cart") cart.add(e.detail.hit.id);
});

Theming

Set CSS custom properties on the element. Styles from your page win over the widget's defaults, in both light and dark mode.

findaro-search {
  --findaro-accent: #2563eb;
  --findaro-radius: 6px;
  --findaro-font: Inter, sans-serif;
  --findaro-card-min: 180px;
}

Behaviour and safety

  • Mobile-first and keyboard accessible: the mode toggle is a radio group and the conversation is an ARIA live log. In AI Mode, Enter sends and Shift+Enter adds a line, product selection uses real checkboxes, and Escape closes the history drawer.
  • Search-as-you-type is debounced and never calls the LLM planner; only a submitted search can.
  • Product links from catalog data are only followed if they are http(s).
  • A missing or placeholder key shows a setup message instead of failing silently.
