Integrate

Widget

<findaro-search> is a Web Component (Shadow DOM, no framework, no dependencies, about 23 KB gzipped with the SDK included). It works in any page: plain HTML, React, Vue, a CMS template.

Install

<script src="__SITE_URL__/findaro-widget.js" data-project="prj_…" data-key="fdr_search_…"
        data-base-url="__API_URL__" defer></script>
<findaro-search></findaro-search>

Settings on the script tag (data-project, data-key, data-base-url, data-locale, data-mode, data-layout, data-starters, data-badges, data-card-actions, data-toggle, data-cards) apply to every <findaro-search> on the page. Attributes on an element override them. Self-hosting? Build the file with npm install && npm run build; it's at packages/widget/dist/findaro-widget.js. Serve it from your own domain.

What it renders

By default (mode="unified") search and the assistant share one surface. See it on the live demo.

  • One search box, no mode toggle. Results update as you type (debounced, rules only, never the LLM). Press Enter to ask: the message goes to /v1/chat and the assistant refines the same results. Follow-ups typed in the same box (“only leather”, “cheaper”, “is the first one leather?”) continue the conversation; a question about the products on screen answers without changing the grid. New search starts over.
  • Understood chips (“Under ₹1,000”, “Black”) that the shopper can remove, and filter pills behind a “Filters” button. After a question, removing a chip continues the same conversation.
  • A compact assistant panel above the results: the latest answer (streamed, with small cards for the products it cites), How I searched, one-click next steps and clarifier rows (“Show slightly over budget”). Earlier turns fold into a “Conversation (N)” expander.
  • A product grid with exact matches first and close matches marked. Each card shows how well the product matches the request (“Matches 2/2”, “Matches 1/2 · not Leather”), badges, price and rating, and Ask, View and your own buttons.
  • Select 2 or 3 products and choose Compare (a side-by-side table built from the listings, shown in the panel) or Ask about these (the next message is about those products only).
  • Ask on a card opens a product drawer: details, suggested questions and a chat about that one product.
  • An empty widget shows a one-line hint and the starters as chips.
<findaro-search badges="material,tags"
                starters="black shoes under 1000|kurta for a wedding|steel water bottle"></findaro-search>

mode="search" is search only, with a Search / Ask AI toggle in the box (Enter searches, Escape clears). With starters set, an empty search box shows them as chips that run a search.

Search and AI Mode as two tabs

To give shoppers your own Search | AI Mode switch (as the live demo does), hide the built-in toggle with toggle="off" and change the mode attribute from your switch. Each mode keeps its own results while you switch: going back to Search restores the search, going back to AI Mode restores the conversation. A search typed in Search mode is put in the AI Mode composer (call el.search(el.query) to ask it right away), and a question asked in AI Mode is searched when you switch to Search for the first time. cards="full" gives the search grid the AI Mode cards (select to compare, “Matches 2/2”, badges, Ask / View); Compare and Ask about these then switch the widget to AI Mode and fire findaro:mode, so keep your switch in sync with that event.

<style> findaro-search { --findaro-thread-height: 70vh; } </style>
<findaro-search mode="ai" toggle="off" cards="full" theme="light"></findaro-search>
<script>
  const el = document.querySelector("findaro-search");
  function show(mode) {
    el.setAttribute("mode", mode);
    if (mode === "ai" && !el.turns && el.query) el.search(el.query); // carry the search over
  }
  el.addEventListener("findaro:mode", (e) => mySwitch.select(e.detail.mode));
</script>

AI Mode (full page)

mode="ai" and layout="page" are kept for existing integrations. In AI mode the widget is a conversational shopping assistant. Products appear inline in the conversation instead of a separate grid. Add layout="page" for a full-page version with a chat history sidebar (collapsible on desktop, a drawer on phones). A new conversation starts with the greeting, the composer and the starter questions centered on the page; after the first message the composer docks at the bottom. Give the element a height; it fills it.

<style> findaro-search { height: 100dvh; } </style>
<findaro-search mode="ai" layout="page" badges="material,tags"
                starters="black shoes under 1000|kurta for a wedding|steel water bottle"></findaro-search>
  • Each answer shows How I searched: what the query was understood as, any filter that was loosened to find results, the result count and the time taken.
  • Cards show how well each product matches the request (“Matches 2/2”, “Matches 1/2 · not Leather”, “Leather not listed”). The API works this out from each listing.
  • Up to three one-click next steps (“Only Copper”, “Under ₹700”) follow each set of results.
  • Shoppers can select 2 or 3 products and choose Compare, which shows a side-by-side table built from the listings, or Ask about these, which sends their next question about those products only.
  • Conversations are saved in the shopper's browser (localStorage, per project, up to 30). The search key is never stored. A conversation reopened after 30 minutes starts a new server session, and the widget re-asks the last question when it needs to.

Without layout="page", mode="ai" shows the same conversation inside the widget box, under the Search / Ask AI toggle (hidden with toggle="off"), with the composer docked at the bottom. Set --findaro-thread-height to give the thread a fixed height (the composer then stays at the bottom of it); style its frame with ::part(thread). With layout="page" mode="search" the page shows the search box, chips, filters and product grid instead; switch between the two by changing the mode attribute. Put an element with slot="sidebar-footer" inside the widget to show it at the bottom of the history sidebar.

Properties and methods

NameWhat it does
el.search(query)Ask programmatically (unified and AI mode), or run a search (mode="search").
el.onProductClick = (hit, event) => …Called when a product is clicked. When set, the widget doesn't follow the product URL.
el.renderProduct = (hit, { display, formatPrice }) => …Your own product card. Return an element, or an HTML string (escape document fields yourself).
el.cardActions = [{ label, onClick(hit) }]Extra buttons on AI Mode cards, after the ones from card-actions. onClick runs unless a findaro:action listener cancels the event.
el.query, el.turnsRead-only: the current search text (or the last question asked), and the number of messages in the conversation.
el.strings = { … }Override any UI text, merged over the locale's defaults.
el.clientInject a preconfigured SDK client (for example with a custom fetch).
 
<script>
  const el = document.querySelector("findaro-search");
  el.onProductClick = (hit) => location.assign(`/p/${hit.id}`);
  el.renderProduct = (hit, { display, formatPrice }) => {
    const card = document.createElement("div");
    card.className = "my-card";
    // textContent keeps catalog data safe
    card.textContent = `${hit.document[display.title]} · ${formatPrice(hit.document[display.price])}`;
    return card;
  };
  el.strings = { placeholder: "Search 10,000 products…" };
</script>

Events

All events bubble and cross the shadow boundary (composed).

EventdetailWhen
findaro:resultsthe search response (total, hits, understood, …)After each search returns.
findaro:product-click{ hit }A product was clicked. Cancelable: preventDefault() stops navigation to the product URL.
findaro:action{ action, hit }A custom card button was clicked (action is its label). Cancelable.
findaro:mode{ mode }The mode changed (your attribute change, the built-in toggle, or Compare / Ask about these in mode="search").
findaro:errorthe errorA request failed.
 
el.addEventListener("findaro:results", (e) => console.log(e.detail.total));
el.addEventListener("findaro:product-click", (e) => {
  e.preventDefault();
  openQuickView(e.detail.hit);
});
el.addEventListener("findaro:action", (e) => {
  if (e.detail.action === "Add to cart") cart.add(e.detail.hit.id);
});

Behaviour and safety

  • Mobile-first and keyboard accessible: in unified mode Enter asks and Escape clears the box, the assistant panel is a labelled region and selection uses real checkboxes; the compare bar stays docked at the bottom of the screen. In mode="search" the mode toggle is a radio group. In AI Mode the conversation is an ARIA live log, Enter sends and Shift+Enter adds a line, product selection uses real checkboxes, and Escape closes the history drawer.
  • Search-as-you-type is debounced and never calls the LLM planner; only a submitted search can.
  • Product links from catalog data are only followed if they are http(s).
  • A missing or placeholder key shows a setup message instead of failing silently.
