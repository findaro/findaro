How it works

Three steps. No schema, no synonym lists.

  1. Send your catalog

    Upload JSON, JSONL or CSV, or push documents over the API. zerch works out which field is the title, the price, the colour or the category from the data itself. You can override any of it.

    POST /v1/projects/{id}/import
file=@catalog.jsonl

  2. Drop in the widget or call the API

    One script tag gives you a complete search UI. Prefer your own UI? Use the headless TypeScript SDK or plain HTTP. The browser key can only search.

    <zerch-search></zerch-search>

  3. Shoppers search in their own words

    Prices, colours, sizes and categories come out of the query and show up as chips they can remove. When nothing matches exactly, zerch says so and shows the closest options.

    "500 ke andar steel bottle"
What you get

Built for real catalogs and the way real people type.

Keyword search fails on “joote under 1k”. Pure vector search shows confident nonsense. zerch does both kinds of retrieval and reads the query first.

Reads the query, not just the words

Price ranges (“under 500”, “1000 se kam”, “₹500-₹1000”, “1.5k”), colours, materials, sizes, brands, audience and categories are pulled out of the query using only the values in your catalog. Units such as “5 L” or “65W” are never mistaken for prices. Everything zerch applied comes back as chips your UI can remove.

“500 ke andar kaale joote” → Under ₹500 · Black · searching “black shoes”

Indian English and Hinglish

Language packs map hundreds of Hinglish words and phrases (“sarson ka tel” → mustard oil). Spelling variants such as joota, juta and jootey match each other, and Devanagari is transliterated, so “जूते” finds “joote”.

Hybrid retrieval

Keyword search (BM25, typo-tolerant) and multilingual semantic vectors, fused into one ranking. “presure coker” still finds pressure cookers.

Honest when nothing matches

Every response says whether the match is good, weak or none. If a filter leaves nothing, zerch relaxes it and tells you which one. Exact matches come first, close matches after, clearly marked.

No schema to write

Field roles (title, price, facet, category, image…) are inferred from your data on the first import. New fields are picked up later. Overrides reindex in the background while search keeps working.

Drop-in widget

<zerch-search> is one Web Component: search box with a Search / Ask AI toggle, removable chips, filter pills, product grid, AI panel and a product drawer. Shadow DOM, mobile-first, keyboard accessible, themeable with CSS variables, about 10 KB gzipped with no dependencies.

Headless SDK and plain HTTP

@zerch/sdk is a typed TypeScript client with zero dependencies, about 1.5 KB gzipped: search, streaming chat, cancellation and retries. Or call the JSON API from any language.

Keys that are safe where they live

Each project has two keys. The search key is read-only and browser-safe: it can only search and chat, and only from the origins you allow. The admin key manages your data and is refused when it comes from a browser.

Ask AI

A shop assistant that only says what your listing says.

Chat mode lets shoppers refine results in conversation (“cheaper”, “sirf cotton”, “not slippers”) and ask about a product the way they would on a product page. The answers stay grounded.

  • The model only sees the products on screen. Prices and other numbers are filled in from your data, not written by the model.
  • Every sentence is checked in code before it streams. Anything not backed by the listing is dropped.
  • If the listing doesn't say, the answer says so (“The seller hasn't listed a warranty”) instead of guessing.
  • General know-how is labeled as general, never presented as a fact about your product.
  • Hinglish in, Hinglish out.

For developers

One script tag, one endpoint.

Same API whether we host it or you do. The full reference is in the docs.

<!-- one script tag + one element; the search key is browser-safe -->
<script src="__SITE_URL__/zerch-widget.js"
        data-project="prj_…" data-key="zk_search_…"
        data-base-url="__API_URL__" defer></script>

<zerch-search locale="hi-en"></zerch-search>

<style> zerch-search { --zerch-accent: #c2410c; --zerch-radius: 10px; } </style>
curl -X POST __API_URL__/v1/search \
  -H "authorization: Bearer $SEARCH_KEY" -H 'content-type: application/json' \
  -d '{"query": "kaale joote 1000 ke andar", "size": 5}'

# → hits, facets, and what was understood:
# "understood": { "semantic_text": "black shoes",
#   "chips": [{ "label": "Under ₹1,000", "remove": [...] }, { "label": "Black", "remove": [...] }],
#   "match_quality": "good", ... }
import { createClient } from "@zerch/sdk";

const zerch = createClient({ projectId: "prj_…", searchKey: "zk_search_…", baseUrl: "__API_URL__" });

const res = await zerch.search("kaale joote 1000 ke andar");
// drop the "Black" chip without a new query
await zerch.search({ query: res.query, patch: res.understood!.chips[1].remove });
curl -N -X POST __API_URL__/v1/chat -H "authorization: Bearer $SEARCH_KEY" \
  -H 'content-type: application/json' -d '{"message": "saree under 1000"}'

event: session   {"session_id": "chs_…", "turn": 1}
event: plan      {"understood": {…}, "delta": {"added": ["Under ₹1,000", "Sarees"]}}
event: results   {"items": […], "total": 10, "match_quality": "good"}
event: clarify   {"question": "Only 1 match under ₹1,000. Want to see options slightly over budget?"}
event: text      {"delta": "Only one saree is under ₹1,000: "}
event: done      {"turn_type": "new", "answer_source": "model"}

FAQ

Questions teams ask us.

Which languages does zerch understand?

English, Indian English and Hinglish (Hindi written in Latin script, with its many spellings). Hindi in Devanagari is transliterated for matching. Query-understanding packs exist for English and Hinglish today.

Is an LLM called on every search?

No. Fast rules handle almost every query. A small LLM planner is used only when the rules can't account for some words. It has a strict timeout with the rules plan as the fallback, and its answers are cached. Search-as-you-type never calls it.

Will the AI chat make things up about my products?

It's built not to. The model only sees the products on screen, numbers come from your data, and every sentence is checked in code before it is shown; sentences that aren't backed by the listing are dropped. If the listing doesn't say something, the answer says that. General advice is labeled as general advice.

Do I need to describe my catalog's schema?

No. zerch infers each field's role (title, price, colour, category, image…) from the data. You can review the inferred schema and override any field through the API.

Is it safe to put the search key in my web page?

Yes, that's what it's for. It's read-only, it can only search and chat, and browser requests are only accepted from the origins you allow for your project. Keep the admin key on your server; browsers can't use it.

Where is my data stored on the hosted service?

In Oracle Cloud's Mumbai (India) region. See the privacy policy for what we process and why.

What counts as a search?

Each call to the search API, including the debounced search-as-you-type requests the widget sends, and each chat turn. If you're about to go over your plan, we'll contact you first; search is never cut off without warning.

Can I start hosted and move to self-hosting later (or the other way)?

Yes. It's the same open-source engine and the same API, so your integration doesn't change; only the base URL and keys do.

Do you have autocomplete, analytics or recommendations?

Not yet. Today zerch does search, query understanding and AI chat over your catalog. We'd rather tell you plainly than promise dates.
